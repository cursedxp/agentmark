# AgentMark project

This project is written in AgentMark: Markdown files ending in `.agent.md` that `agentmark build` compiles to a Rust binary. You are writing AgentMark, not Rust.

## The one source of truth

Read `docs/reference.md` of the AgentMark checkout before you write anything. It is the whole language in one file: every declaration, every statement form, every error message, with examples that are tested. Do not guess syntax from other languages and do not invent statements. If `docs/reference.md` does not show it, it does not exist; ask the human.

If this project lives outside the AgentMark checkout, keep a copy or a link of that file next to the project (for example `docs/agentmark-reference.md`) and read that one.

## Workflow

1. Edit one `.agent.md` file.
2. Run `agentmark check .` (or the file) straight away. Fix every error before touching anything else. The messages say what is wrong and often what to write instead.
3. Run `agentmark fmt .` so the files are in the one canonical style. `agentmark fmt --check .` only reports.
4. Run `agentmark lint .` and fix the warnings, or ask before adding to `[lint] deny`.
5. Test without side effects: `agentmark trace . --mock --fixtures fixtures/<name>` prints what the program did, one JSON object per line. Compare traces, not generated Rust.
6. `agentmark doc .` prints a readable page of the project, including what each block can touch.

Run `check` after every edit, not at the end. A file that was green five edits ago tells you nothing.

## Rules

* Never write Rust, except inside a `## Rust: <name>` block when the human asked for it or no bound library does the job. Never edit generated code under `target/` or an `-o` output folder; change the `.agent.md` source.
* Never edit `rust/connect.rs` beyond filling in the tool implementations the human asked for.
* Effect lines in `bindings/*.agent.md` are for humans to approve. Never change `- effect: unverified` there, and never loosen a block's tools to silence `check`. Show the human what the library can touch and let them approve it. `--allow-unverified` is for exploring, not for finishing.
* A `## Rust` block needs an `- effect:` line. Declare the honest class (never a weaker one to pass `check`) and tell the human, because that line is trusted, not verified.
* Keep a block small: one statement per line, at most 120 characters, at most 3 levels of nesting (`check` enforces this). Put a `>` description above every agent, record, rule and function.
* Tools come from `tools.toml`. Do not call a tool or a verb that is not listed there; add it to the manifest only when the human asks.
* Follow every `ask model` with a `guard:` on its answer (the lint `prompt-in-loop` wants it inside a `for each`). Name a money, duration or URL literal used more than once as a `# Constant` (the examples keep them in `constants.agent.md`).
* No secrets in files. Keys come from the environment (`ANTHROPIC_API_KEY`).

## Where things live

```
agentmark.toml      name, version, targets, [lint], [models], [rust.dependencies]
tools.toml          the tools a program may use, their verbs and effect classes
main.agent.md       imports and a single `# Run` listing what the binary starts
records/            one # Record per file
rules/              one # Rule per file
agents/             one # Agent per file
functions/          one # Function per file
bindings/           generated by `agentmark bind`; reviewed by a human, committed
fixtures/           model answers, tool data and expected traces for --mock
rust/connect.rs     the real tool implementations (written once, then yours)
```

A new agent is a new file in `agents/` plus one line in the `# Run` of `main.agent.md`, with a `# Import:` for it.

## When you are stuck

Say what you tried and what `check` answered. Do not work around the checker.
